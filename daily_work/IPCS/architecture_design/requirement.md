IPCS_001: IPCS应支持在属于同一处理器或不同处理器的不同内核上运行的应用程序之间的点对点双向通信
IPCS_002: 部署在 AutosarOS 上的 IPCS 应支持安全 规范ASIL-D
IPCS_003: IPCS内核应该是和硬件平台和字节序无关的
IPCS_006: IPCS 应作为驱动程序在 Threadx 下运行
IPCS_009: 每个特定层（platform、os、phy、transport）都应包含在一个单独的文件夹中（因此只需删除该文件夹即可删除支持）
IPCS_010: 传输层的设计应允许基准测试和吞吐量估计
IPCS_011: IPCS 应可在 Windows 主机上构建
IPCS_012: 代码应该可以通过单元测试在主机上进行测试。组件应该很容易被模型替换。
IPCS_013: 为了满足信息安全以及功能安全的验证要求，需要模糊测试。
IPCS_014: SHM 驱动程序应支持多个通信通道（数据流）
IPCS_015: 消息顺序应保留在通信通道/流中
IPCS_016: SHM 驱动程序应支持每个通道的多个缓冲池
IPCS_017: SHM 驱动程序应支持在所有内核上同时运行多个传输（高效内核利用率）
IPCS_018: SHM 驱动程序应具有零拷贝 API 和实现
IPCS_019: SHM 驱动程序应具有异步（基于通知）接收 API
IPCS_020: 实现应确保两个通信 SHM 驱动程序之间不受干扰（内存保护）
IPCS_021: SHM 驱动程序应支持非托管通道，其中缓冲区管理被禁用，应用程序拥有整个通道内存
IPCS_022: IPCS 应确保触发的虚拟中断不会向应用程序发送旧数据
IPCS_023: IPCS应确保丢失的中断不会导致传输的数据丢失
IPCS_024: IPCS应与AUTOSAR 4.4或更高版本兼容
IPCS_025: 内存池中缓冲区的大小和数量应是可配置的
IPCS_028: SHM 驱动程序应该支持MSCM 核间中断作为发送接收方的通知方式
IPCS_029: 软件组件应使用静态内存分配。
IPCS_030: 开发用于在设备上运行的源代码应符合编码指南文件。
IPCS_031: SHM 驱动程序应支持多对内核（多个实例）之间的通信
IPCS_034: 驱动程序应验证来自应用程序的公共 API 参数
IPCS_035: 驱动程序应验证通道类型对请求的操作是否有效
IPCS_036: IPCS应设计用于低延迟和小尺寸的紧密分布的嵌入式系统。客户可以选择在硬件、操作系统和传输支持方面准确构建他们需要的东西。
IPCS_038: IPCS子系统应按照辰至汽车质量流程开发为汽车生产级软件。
IPCS_005: IPCS 应作为复杂驱动程序在 AutosarOS 下运行
IPCS_039: SHM 驱动程序应支持轮询方法 （IRQ_NONE）
