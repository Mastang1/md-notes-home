

**NXP Semiconductors** **S32G 4.10.0 跨平台通信框架 (IPCF)** **版本 1.0** **修订版 1 — 2024年5月31日** **发布说明**

# 1 简介

跨平台通信框架 (IPCF) 是一个子系统，它使运行在多个同构或异构处理核心（位于同一芯片或不同芯片上）以及不同操作系统（AUTOSAR, Linux, FreeRTOS, Zephyr 等）上的应用程序，能够通过各种传输接口（共享内存等）进行通信。

IPCF 专为 NXP 嵌入式系统设计，具有低延迟和极小占用的特点。它提供了零拷贝 API，客户可以直接使用以获得最大性能、最小开销和低 CPU 负载。该驱动程序通过仅在本地内存域中执行所有写入操作，确保了本地和远程共享内存之间的免干扰 (freedom from interference)。

客户可以使用 XRDC/SMPU 外设对其软件实施内存保护。

# 2 本次发布的新增内容

变更列表：

- IPCF 驱动程序使用哨兵 (sentinel) 检查缓冲区溢出。由于此新功能，IPCF 驱动程序不再与旧版本兼容。
- IPCF 驱动程序已更新至 AUTOSAR 版本 R21-11。
- IPCF 驱动程序现在兼容 C++。
- 增加了非托管通道大小的限制。
- IPCF 驱动程序支持用于通信的缓存内存 (cached memories)。此功能仅具有 EAR 质量级别。
- IPCF 驱动程序和示例应用程序已更新至 NXP Linux BSP40。
- 本次发布对于 S32G3xx 具有 RTM 质量级别。
- 本次发布对于 S32G27x 具有 RTM 质量级别。

# 3 入门指南

## 3.1 软件包内容

本次发布包含适用于 S32G274A 平台的 NXP IPCF。

软件包内容：

- **跨平台通信框架 (IPCF) 发布说明**：描述此 IPCF 发布的内容、限制和支持的设备。
- **跨平台通信框架 (IPCF) 用户手册**：描述 IPCF 驱动程序、如何使用它、如何针对不同操作系统和硬件平台进行编译和配置，并介绍驱动程序 API。

- **更新站点 (Update Site)**：包含 S32 Design Studio 的更新站点。
- **独立安装程序 (Stand-alone Installer)**：包含驱动程序代码和 makefile 示例。
- **质量包 (Quality Package)**
- **安全包 (Safety Package)**
- **软件内容注册表 (SCR)**

## 3.2 安装 Design Studio

IPCF 作为 S32 Design Studio 的扩展交付。

IPCF 作为 S32 Design Studio 的更新站点交付。在这种情况下，必须在安装 RTD 软件包之后，按照以下步骤进行安装：

- 启动 S32 Design Studio 并选择一个工作空间。
- 选择 Help（帮助） - S32 Design Studio Extension and Updates（S32 Design Studio 扩展和更新）。
- 点击 Add Update Site（添加更新站点）并选择包含 IPCF 发布版本的归档文件。
- 勾选要安装的 IPCF 软件包并继续安装过程。
- 安装完成后，可以将 IPCF 添加到新的 S32DS 项目中，或者可以使用软件包中提供的 IPCF 示例。

## 3.3 安装 EB Tresos

按照安装程序步骤操作。 默认情况下，安装程序将在安装目标目录和选定的 EB Tresos 安装之间创建一个链接。 如果您选择不创建链接，您可以稍后手动创建一个，或者可以将 "Ipcf_TS_T40D11M410I0R0" 目录复制到 "Tresos\plugins" 目录中。

# 5 IPCF S32G 的已知问题和限制

加载 S32 Design Studio 后，必须生成配置文件（双击 mex 文件并更新代码）。

链接器会抛出关于枚举大小的警告，这是由于使用了 "-fno-short-enums" 选项：“跨对象使用枚举值可能会失败”。驱动程序不使用任何库枚举类型，因此没有功能影响。

如果之前从 FLASH 运行过，从 RAM 调试 IPCF 示例应用程序可能会失败。在这种情况下，用户必须擦除所有 FLASH 才能正确运行 IPCF 示例。

会抛出关于堆栈使用的警告。有关参考，请参见启动文件中核心异常的实现。

IPCF 示例应用程序未在 PE Micro 调试器上进行测试。

互斥区域 (Exclusive areas) 目前未在 IPCF 驱动程序中使用，因此无需定义任何互斥区域。

驱动程序不支持在同一核心上运行的多个实例使用相同的 MSCM 核对核定向中断。

IPCF 驱动程序在 AutosarOS 实现中仅支持每个实例一个 ISR 处理程序。

如果在发送/接收消息时释放实例，IPCF 驱动程序无法确保通信状态。

要使用带有当前 IPCF 版本 (4.10.0) 的 NXP Linux BSP 40.0，用户必须更新 NXP Linux BSP 40.0 镜像中的预构建 IPCF 模块。这是必要的，因为 NXP Linux BSP 40.0 镜像是使用 IPCF 版本 4.9.0 构建的。有关更新预构建模块的信息，请参阅用户手册。
