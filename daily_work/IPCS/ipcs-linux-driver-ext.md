# IPCF Shared Memory (ipc-shm) 用户手册

## 1. 产品概述

NXP Linux IPCF Shared Memory (ipc-shm) 驱动程序旨在实现 Linux 系统与同一处理器不同核心上运行的 RTOS 应用程序之间的高效通信。该方案利用共享内存作为物理传输介质，通过无锁环形缓冲区机制，确保了异构核心之间的数据交换既快速又可靠。

## 2. 驱动架构

本产品包含两类核心驱动组件，以适应不同的应用场景：内核空间驱动与用户空间驱动。

### 2.1 Linux 内核驱动 (Kernel Driver)

该驱动作为 Linux 内核模块（Out-of-Tree 模块）集成在 NXP Auto Linux BSP 中。

- **功能**：负责底层共享内存的映射、中断处理（发送与接收）以及核心间的同步。
- **适用场景**：适用于需要在 Linux 内核空间直接处理数据或与其他内核子系统交互的场景。
- **源码位置**：通常位于 `os_kernel` 目录（参考文件结构）。

### 2.2 用户空间驱动支持 (User-space Driver Support)

为了允许应用程序直接在用户空间进行通信，IPCF 提供了相应的支持库和驱动接口。

- **组件**：
    - **静态库 (`libipc-shm`)**：用户空间应用链接此库以调用通信 API。
    - **底层接口**：支持 UIO (User-space I/O) 驱动或字符设备 (CDEV) 驱动。初始化时，静态库会自动加载相应的内核模块。
- **功能**：允许用户应用直接读写共享内存，旁路内核协议栈，减少系统调用开销。
- **源码位置**：相关代码位于 `os_uio` 及库文件目录中。

## 3. 技术规格与配置

### 3.1 硬件参数配置

驱动程序 API 级别提供五个关键的硬件相关配置参数：

1. **TX 中断 ID**：发送中断（通知远程核心）。
2. **RX 中断 ID**：接收中断（本地核心接收通知）。
    - _注意_：TX 和 RX ID 必须不同。ID 范围取决于平台（如 S32G3xx 为 [0..11]，S32V234 为 [0..3]）。
3. **本地核心 ID (Local Core ID)**：指定被远程核心中断的目标核心。
4. **远程核心 ID (Remote Core ID)**：指定要被中断的远程核心。
5. **受信任核心 (Trusted Cores)**：指定哪些核心有权访问本地核心的中断状态寄存器。

### 3.2 内存与并发限制 (Cautions)

- **内存访问**：驱动程序提供对映射为**不可缓存 (Non-cachable)** 的物理内存的直接访问。
    - _警告_：应用程序必须确保在共享内存缓冲区中进行**对齐访问 (Aligned Accesses)**。使用可能进行非对齐访问的函数（如某些字符串处理函数）时需格外小心，否则可能导致异常。
- **线程安全**：
    - 驱动程序在**单生产者-单消费者 (Single-Producer - Single-Consumer)** 模型下是线程安全的。
    - **多实例**：驱动程序对于不同的实例是线程安全的，但对于**同一个实例**则不是。即同一通道不应有多个线程同时进行 Push 或 Pop 操作。
- **无干扰设计**：驱动程序通过仅在本地内存中执行所有写操作，确保了本地和远程内存域之间的互不干扰。

## 4. 示例应用程序 (Sample Applications)

`ipc-shm` 提供了多种示例代码以展示不同层级的集成方式。所有示例均演示了与 RTOS 应用程序进行的 Ping-Pong（往返）消息通信。

### 4.1 内核空间示例 (Kernel Sample)

- **目录**：`sample`
- **描述**：这是一个标准的内核模块示例。它演示了如何在内核驱动层面初始化 IPCF，发送消息给远程 RTOS，并在收到回复后触发回调。
- **工作模式**：
    - **中断模式**：默认行为，使用核间中断通知。
    - **轮询模式**：如果禁用了 TX 中断（设置为 `IPC_IRQ_NONE`），远程应用需轮询消息；反之亦然。
- **操作方式**：通过 `sysfs` 接口（如 `/sys/kernel/ipc-shm-sample/ping`）控制发送消息的数量和启动通信。

### 4.2 多实例内核示例 (Multi-Instance Kernel Sample)

- **目录**：`sample_multi_instance`
- **描述**：演示了在同一系统上同时运行两个独立的 IPCF 通信实例。
- **应用场景**：适用于 Linux 需要同时与多个不同的远程核心（例如一个 M7 核心和一个 DSP 核心，或者两个不同的 M7 核心）进行通信，或者与同一核心建立多条隔离通道的场景。
- **操作方式**：会生成不同的 `sysfs` 节点（如 `instance0`, `instance1`）供用户分别控制。

### 4.3 用户空间示例 (User-space Sample)

- **目录**：`sample_user` (以及 `sample_multi_instance_user`)
- **描述**：这是一个可执行的 ELF 应用程序，链接了 `libipc-shm` 库。
- **特点**：
    - 利用 UIO 或 CDEV 机制映射内存。
    - 展示了如何在应用层代码中直接调用 `ipc_shm_init`, `ipc_shm_send` 等 API。
    - 编译时可通过设置 `IPC_UIO_MODULE_DIR` 指定目标板上 UIO 内核模块的路径。

## 5. 支持与故障排除

- **平台支持**：支持 NXP S32 系列处理器（具体列表见各版本发布说明）。
- **常见问题**：
    - 若通信无响应，请首先检查中断 ID 配置是否与硬件参考手册（Reference Manual）中的中断路由表一致，注意驱动配置的中断 ID 可能与异常号不同。
    - 若出现总线错误（Bus Error），请检查是否在共享内存区域执行了非对齐的读写操作。
