
在 VectorCAST 的 Environment User Code 中，从 Header 到 Additional Unit Bodies 共包含 13 个可注入自定义代码的阶段。它们赋予了您在测试执行生命周期中处理复杂任务的能力，各阶段自定义代码的用途详细说明如下：

1. **Header**：**通常出现在源文件顶部的源代码**。该区域主要用于包含 `#include` 文件引入指令或 `#define` 宏定义。
2. **Data**：用于**提供环境用户代码所需的对象定义**（如类型定义、全局对象和附加子程序）。您可以通过该区域编写代码从文件读取数据、调用初始化例程，或基于动态条件分配和验证数据对象。
3. **Harness Init**：这段代码在**整个测试框架（Test Harness）执行的最开始仅运行一次**，用于完成环境级别的全局初始化工作。
4. **Test Case Init**：这段代码在测试框架**每次真正调用被测单元（UUT）之前立即执行**，专门用于单个测试用例级别的前置数据准备与初始化。
5. **UUT Timer Start**：这段代码在**即将进入对 UUT 的调用之前执行**，通常专门用于启动性能测试计时器。
6. **UUT Timer Stop**：这段代码在**刚从对 UUT 的调用返回之后立即执行**，通常用于停止计时器。
7. **Stub Entry**：在**进入被打桩的子程序（Stubbed Subprogram）时执行**。它的执行时机在“Configure Stubs”中定义的 Beginning User Code（桩开始处代码）之后。
8. **Stub Processing**：这是所有桩函数的公共处理代码，**每次调用任何桩函数时都会被执行**。
9. **Stub Exit**：在**退出被打桩的子程序时执行**。它的执行时机在“Configure Stubs”中定义的 Ending User Code（桩结束处代码）之前。
10. **Test Case Term**：在 **UUT 将控制权返回给测试框架后立即执行**。它通常用于在单个测试用例结束后，检查受特定测试用例影响的数据流或执行清理。
11. **Harness Term**：在**整个测试框架执行完毕且即将退出前执行一次**。这通常包括将最终数据保存到文件，或执行全局的其他清理处理操作。
12. **Additional Unit Specs**：用于编写您想要额外添加到测试框架中的**附加代码单元的规格/声明部分（Specification）**。
13. **Additional Unit Bodies**：用于编写额外添加到测试框架中的**附加代码单元的实现部分（Implementation）**。例如，您可以将非交付代码但测试必需的打印工具、计时例程或复杂的数据设置例程作为独立的源文件（单元）实现并挂载到测试框架中。
