### 🎓 VectorCAST 环境配置教程：深度解析 Choose UUTs & Stubs 选项卡

该选项卡是整个单元测试环境的“控制中枢”，您在这里决定哪些代码作为真实被测对象（UUT），哪些外部依赖需要被打桩（Stub），以及哪些函数或数据类型需要暴露给测试用例。

#### 一、 核心基础面板控件

**1. Unit Names (可用单元列表) 与 Units Under Test (被测单元列表)**

- **作用**：`Unit Names` 显示了从源码目录中扫描到的所有可测试文件。`Units Under Test` 则是您真正要进行测试的目标集合。
- **使用说明**：选中左侧的某个源码文件，点击中间的“向右箭头”或直接双击，即可将其移动到右侧的 `Units Under Test` 列表中。若要移除，则点击向左箭头将其移回。
- **💡 进阶技巧 (SBF vs UUT)**：移入右侧后，文件默认标记为带有循环箭头的 **`sbf`** (Stub By Function，按函数打桩) 图标。点击该图标，可以将其切换为 **`uut`** (普通被测单元) 图标。普通 UUT 无法在测试用例中对单元内部的子函数进行动态打桩隔离。

**2. Stub Dependencies (打桩依赖策略单选按钮)**

- **作用**：决定测试框架如何处理 UUT 调用的底层依赖文件。
- **使用说明**：
    - **All (默认)**：按函数原型（Prototype）对所有底层依赖打桩。
    - **None (Source-Files)**：不对任何依赖打桩，使用真实的源码进行串行编译。
    - **None (Object-Files)**：不对任何依赖打桩，而是使用预先编译好的目标文件（通过 vcshell database 获取）并行编译，速度更快。
    - **Custom**：开启自定义打桩树。点击下方的 `Show Dependency View` 生成完整的调用依赖树后，您可以将特定的底层文件拖拽到 `STUB` (强制打桩) 或 `DONT_STUB` (使用真实代码) 图标下，实现极其精细的混合隔离控制。

#### 二、 高级配置选项卡 (核心剖析)

在界面最右侧，有一列垂直排列的选项卡，它们赋予了您对测试沙盒的绝对控制权。

##### 1. Unit Options (单元编译选项)

- **作用**：为特定的源文件添加专属的编译器指令或宏定义，而不会影响环境中的其他文件。
- **使用说明**：选中选项卡后，在左侧点击某个单元，点击右侧出现的编辑图标，在弹出的窗口中输入特定的编译参数（例如 `-D TEST_DEFINE`）。环境编译时会将这些专属参数与全局参数合并使用。

##### 2. Classes of Interest (关注的类)

- **作用**：仅限 C++ 环境。用于强行暴露并测试那些仅在头文件中定义（如 inline 成员函数）而没有在 `.cpp` 文件中实现的类。
- **使用说明**：点击绿色的 **`+`** 按钮，输入您需要测试的类名（支持 `*` 通配符）。打钩选中后，该类的所有成员函数都会出现在测试树中供您测试。

##### 3. Library Stubs (标准库函数打桩)

- **作用**：专门用于拦截并重写 C/C++ 标准库函数（如 `malloc`, `printf`），通常用于模拟极其难以触发的系统级故障（如内存分配失败）。
- **使用说明**：点击绿色的 **`+`** 按钮，输入库函数名（如 `malloc`）并打钩。构建后，该函数会在参数树中变为桩函数，允许您通过输入值强行使其返回 `NULL`。

#### 三、 “四大微调神器”详细解析 (+/- Stubs 与 +/- Testable Functions)

这四个选项卡是解决复杂代码依赖、解决链接冲突的“终极武器”。

##### 🌟 4. + Stubs (Additional Stubs / 附加打桩)

- **作用**：默认情况下，VectorCAST 只会为 UUT 中**被真实调用过**且找不到实体代码的函数生成桩。但有时您可能会在**测试用户代码 (User Code)** 中调用某个外部函数，由于 UUT 没调用它，工具不会自动生成桩，从而导致链接时报“未定义”错误。`+ Stubs` 就是为了解决这个问题，强制系统为该函数生成一个桩实体。
- **使用说明**：
    1. 点击 `+ Stubs` 选项卡。
    2. 点击绿色的 **`+`** 按钮，在弹出的窗口中输入需要强制打桩的函数名（例如 `lib_funct*`，支持通配符），点击 OK。
    3. 确保函数名前面的复选框处于勾选状态。
    4. 环境构建后，这个额外的桩就会出现在参数树中供您操控。

##### 🌟 5. - Stubs (Suppressed Stubs / 抑制打桩)

- **作用**：强行禁止 VectorCAST 为某个特定的函数生成桩代码。如果您决定在其他地方手工提供这个函数的真实实现（例如在 Unit Appendix User Code 中写了一个模拟器），或者链接某个特定的动态库，就必须用此功能先“抑制”自动打桩，否则会引发“函数重复定义 (Multiple Definition)”的编译报错。
- **使用说明**：
    1. 点击 `- Stubs` 选项卡。
    2. 点击绿色的 **`+`** 按钮，输入要禁止打桩的函数名并点击 OK。
    3. 确保打钩。环境构建时，测试框架将彻底忽略该函数，不再生成桩外壳。

##### 🌟 6. + Testable Functions (Additional Testable Functions / 附加可测试函数)

- **作用**：强制将被测文件中的某个隐藏函数（例如因为关闭了全局 inline 测试选项而未能暴露出来的头文件内部函数）提升为“可测试状态”，使其出现在左侧的测试用例树中供您点击和创建用例。
- **关键特性**：它的优先级是最高的。即使一个函数同时被配置为“抑制可测试 (- Testable)”，只要在这里配置了附加，它依然会被强制暴露为可测试。
- **使用说明**：
    1. 点击 `+ Testable Functions` 选项卡。
    2. 点击绿色的 **`+`** 按钮，输入目标函数名（支持 `*` 通配符）并确认。
    3. 确保打钩激活。构建后，您就可以针对这个函数独立创建测试用例了。

##### 🌟 7. - Testable Functions (Suppressed Testable Functions / 抑制可测试函数)

- **作用**：将某些不需要单元测试的函数（例如某些系统生成的胶水代码、或者尚未开发完毕的废弃函数）从测试用例树（Test Case Tree）和参数树的 `<<SBF>>` 列表中彻底隐藏和屏蔽。
- **使用说明**：
    1. 点击 `- Testable Functions` 选项卡。
    2. 点击绿色的 **`+`** 按钮，输入您想屏蔽的函数名（如 `Manager::PlaceOrder` 或使用通配符）。
    3. 勾选激活后，环境构建完成时，这些函数在 UI 上将完全“隐身”，避免测试人员误操作或被迫为其编写无用的测试用例。

---

##### 8. Not Supported Types (不支持的数据类型)

- **作用**：在对极其庞大的系统进行打桩时，如果系统中包含海量极其复杂的结构体或枚举（enum），生成的测试驱动代码（Test Harness）体积会非常庞大，可能导致内存受限的嵌入式目标板无法装载。此选项用于声明某些类型为“不支持”，从而阻止框架为它们生成控制代码，大幅瘦身框架体积。
- **使用说明**：点击该选项卡，点击 **`+`** 按钮输入需要抑制的类型名（如 `enum_OrderType`）。副作用是：一旦禁用，您将无法在图形界面（UI）参数树中直接点击设置该类型的值，而必须通过手写 User Code (C代码) 的方式来对其进行赋值测试。
